Optimasi Query Laravel Eloquent untuk Data Besar

Beberapa teknik praktis untuk membuat aplikasi Laravel tetap responsif saat menangani dataset dengan jutaan baris.

Saat aplikasi Laravel mulai menangani data dalam skala besar, performa query sering kali menjadi bottleneck pertama yang dirasakan. Halaman yang sebelumnya responsif tiba-tiba memerlukan waktu beberapa detik untuk memuat. Artikel ini membahas tiga teknik fundamental yang saya terapkan secara rutin: eager loading, pemilihan kolom spesifik, dan query caching.

1. Eager Loading untuk Mengatasi N+1

Masalah N+1 query adalah klasik di dunia ORM. Ketika kita memuat daftar model beserta relasinya tanpa eager loading, Laravel akan menjalankan satu query untuk model utama, kemudian satu query tambahan untuk setiap relasi yang diakses.

// Hindari: N+1 problem
$users = User::all();
foreach ($users as $user) {
    echo $user->profile->bio;
}

Solusinya adalah menggunakan with() untuk eager load relasi yang dibutuhkan:

// Gunakan eager loading
$users = User::with('profile')->get();
foreach ($users as $user) {
    echo $user->profile->bio;
}

Perbedaannya sangat signifikan. Jika ada 100 user, contoh pertama menjalankan 101 query, sedangkan contoh kedua hanya menjalankan 2 query.

2. Select Kolom Spesifik

Secara default, Eloquent memilih semua kolom dari tabel (SELECT *). Saat tabel memiliki banyak kolom atau kolom dengan tipe data besar seperti TEXT dan JSON, ini bisa memperlambat transfer data dari database ke aplikasi.

// Hanya pilih kolom yang diperlukan
$posts = Post::select('id', 'title', 'slug', 'published_at')
    ->with('author:id,name')
    ->get();

Tips tambahan: jika Anda sering menggunakan subset kolom yang sama, pertimbangkan untuk membuat scope di model agar query tetap DRY.

3. Query Caching untuk Data Jarang Berubah

Tidak semua data perlu diambil dari database setiap kali halaman dimuat. Data seperti daftar kategori, pengaturan situs, atau daftar provinsi sangat cocok untuk di-cache.

$categories = Cache::remember('categories.all', 3600, function () {
    return Category::all();
});

Laravel menyediakan berbagai driver cache: file, database, Redis, dan Memcached. Untuk produksi, Redis adalah pilihan terbaik karena performa dan fitur expiration yang handal.

Kesimpulan

Optimasi query bukan tentang melakukan segalanya sekaligus, melainkan mengidentifikasi bottleneck melalui profiling dan menerapkan solusi yang paling berdampak. Gunakan Laravel Debug Bar atau Telescope untuk memantau query yang dijalankan, lalu terapkan teknik-teknik di atas secara bertahap.

"Premature optimization is the root of all evil" — tapi ignorance of obvious bottlenecks is just as bad.
